## SECTION 2 — THE WORK, IN ORDER

1. **The forced-wake amplification is now the MAJORITY of renders** — 55%
   unattributed (~12/min, absolute rate unchanged all evening). With write
   churn gone, coalescing signal-less wakes (eval resolutions, future
   completions re-rendering the root once each) is the biggest remaining
   render lever. `renders_unattributed` in `component_window` is the number to
   move; `FORCED_WAKE_TOTAL` (launch.rs) counts the wakes themselves.
2. **MainSurface renders on every root pass** — it reads `state` in its body,
   so props memoization cannot shield it. Its own body is cheap (~0.4 ms); the
   `app` root pass is ~26 ms mean. Narrowing = split app()'s rsx so the layout
   chrome re-renders without re-running the whole root, or convert
   MainSurface's reads to peeks + narrow signals.
3. **HostHealth's 8 inline daemon awaits** in the js_event branch
   (`viewport.rs`, search `HostHealth`) — routine traffic, each can hold the
   loop for a round trip. Same treatment as the write: spawn with in-flight
   latches, results back on a channel. **read_poll_apply's** 8 inline recovery
   awaits are the same family, plus its ~2900-line synchronous body.
4. **app-control Describe verbs are cached, not moved** — still on the UI
   thread. The real fix is serving read-only verbs off-thread from a published
   snapshot (RenderSnapshot is nearly plain data; an ArcSwap the OS poll
   thread reads would take agent probes off the UI thread entirely).
5. **The byte-plane end-state**: terminal bytes over a dedicated localhost
   WebSocket, exactly the pattern `vendor/dioxus-desktop/src/edits.rs` already
   proves for edits — input AND echo bypass the UI thread in both directions.
   That is also the substrate genuine multi-viewer co-browse needs (the
   constitution's hard half). Design before code; it touches the daemon.
6. ~~The ping-liveness render~~ **DONE (the confirmed-roots fold, 74430ab3):**
   a changed-nothing ping reply is prechecked read-only
   (`sidebar_ping_would_change_reactive_state` — its refetch mirror is locked)
   and records liveness in a non-reactive side table every liveness reader
   max()es in. Also in the fold: the health-sample gate skips the
   active-visible session and a hidden sidebar, and its throttle relaxed
   750ms→2.5s. STILL OPEN from the dossier: the restore-card 1 Hz tick
   (animate the card component-locally), the retarget noop write (needs the
   scheduling fields out of the signal — the architecture item), and the
   dossier's headline: split hot leaf state into narrow Signals.
   The dossier itself: `~/.yggterm/relay/dossier-input-heat-20260821.md`.
7. Small queue debts filed in the blink-storm entry: `remote_preview_dirty_epoch`
   is a write-only map; `recent_ui_telemetry` still lives inside the render
   signal.
8. The webview edit-stall class now has an instrument (this lane, post-roll):
   `edit_flush_timeouts` counts flush-gate releases in vendored dioxus-desktop
   (each one = the whole VirtualDom frozen ~2s while the event loop looked
   healthy), and the working-flags tick files a `webview_edit_stall` ytrace
   incident on any delta of it or of `edit_faults`. The COUNTER is landed;
   whether the stalls' ROOT (occluded window stops rAF acks?) needs a fix is

  `Callback::eq` is ptr_eq on a box rsx re-allocates every render. Locks:

  `an_unchanged_shell_snapshots_equal_twice`. Verified against dioxus-core
