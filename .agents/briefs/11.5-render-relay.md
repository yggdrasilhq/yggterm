## SECTION 1 — THE FIRST THING TO DO, AND IT IS A MEASUREMENT

**The lock-scope hoist is on `main` but was NOT in the 3.1.6 deploy.** Its marker
is `terminal_read_owner_resolve`; confirm with
`strings -a <daemon binary> | grep -c terminal_read_owner_resolve`.

⛔ **VERIFY A DEPLOY AGAINST THE RUNNING PROCESS, NEVER THE BINARY.** A deploy
writes binaries; the daemon swaps itself, **the GUI cannot swap its own image in
place**. This lane found three fixes reported "marker-verified" and not running,
while the owner was locked out of typing. The check is
`grep -c <marker> /proc/<pid>/exe`, `readlink /proc/<pid>/exe` (a `(deleted)`
suffix means replaced underneath it) and the process start time vs the deploy.

**Then take the acceptance read you own.** The pre-fix baseline, captured on `dev`
before the hoist deployed, is recorded in the queue entry:

| | |
|---|---|
| slow lock waits | 262 |
| `terminal_read` | **164 (62.6%)** |
| p50 · p95 | 112.3 ms · 10,247 ms |
| max | **84,693 ms** |

⇒ **After the hoist deploys, `terminal_read` must fall out of the top of that
distribution. If it does not, the hoist is wrong and that belongs in the queue
entry, loudly.** `waited_us` is MICROSECONDS — reading it as ms turns an 84 s
stall into a non-event.

## SECTION 2 — THE WORK, IN ORDER

1. **The preserved-owner family sweep** (approved by 11.0, sequenced AFTER the
   lock hoist has soaked, so the pattern is proven on `terminal_read` first).
   `TerminalSnapshot`, `TerminalRetainedSnapshot` and the rest still make their
   cross-daemon round trip from inside the handler with the runtime lock held.
   Together they are about as much of the slow-wait distribution as
   `terminal_read` alone. ⭐ **Factor the resolve/booking dance ONCE** — it is
   identical across all of them — rather than pasting the `terminal_read` hoist
   five times. Approved as part of the same subset: give a PROXIED call a much
   tighter budget than a direct one, since a preserved owner silent for ~1 s is a
   different problem from a busy one, and let the fall-through serve locally.

2. **Symptoms 8 and 9 — repro FIRST.** Three candidates, none eliminated:
   (a) the daemon retains 10,000 scrollback rows and the client's re-attach
   replay caps at 900; (b) `retained_rehydrate_should_skip_before_read` returns
   before seeding when the host is already live; (c) for CC's bottom
   specifically, the reveal reconcile never writes on a WORKING surface, which is
   exactly the state CC is in when you switch to it mid-turn.
   ⛔ **DO NOT PATCH THE SEEDING POLICY WITHOUT A REPRO THAT SEPARATES THEM.**
   `terminal_retained_replay_policy.rs` documents two prior reversions from
   changing it on a magnitude heuristic. A third blind change is malpractice.

3. **The render falsifier is unmet and blocked on human traffic.** Best numbers,
   taken during a post-restart attach storm: keystroke→pty p50 1 ms / p95 147 ms;
   pty→render p50 64 ms / p95 **119 ms** against a <50 ms bar. The quiet window
   afterwards had **zero keystrokes** — nothing to measure.
   ⛔ **DO NOT MANUFACTURE SAMPLES BY TYPING INTO LIVE ROWS.** The probes are
   deployed and will collect it the next time a human works.

4. **`read_poll_apply` holds the loop.** With the read I/O off-loop, what remains
   is the PROCESSING of the read result: 1149 ms and 719 ms during the storm, and
   **574 ms fifteen minutes after it**, so not purely storm-related. n is small;
   get the quiet-state distribution before filing it.

## SECTION 3 — TRAPS THIS LANE PAID FOR

- ⛔ **`input-check` WRITES A MARKER — it types into the row.** It is the natural
  next command for diagnosing a wedged session and it is destructive on one a
  human is using. `server gate-screen` is the read-only door.
- ⛔ **A hand-rolled vt100 lies about coverage.** Gradient banners are drawn as
  SPACES carrying a background colour, which a "is the text blank" test scores as
  unpainted; alt-screen and scroll regions are easy to skip. Use
  `scripts/cli-viewport-probe`, which feeds a real PTY to the same `vt100` crate
  the daemon parses with and reports `bg_only_cells`.
- ⛔ **`pgrep -f <pattern>` matches the searcher's own shell.** It cost this lane
  a build-wait loop that waited on itself forever. Match on `/proc/<pid>/exe`.
- ⛔ **`ytrace tail --lines N`**: too small silently caps at 20; too large can
  return exactly N records from ROTATED generations whose newest predates the live
  file's tail. Check the newest timestamp against the clock, or read
  `~/.yggterm/ytrace.jsonl` directly.
- ⛔ **A startup event is emitted by every short-lived CLI process**, not only the
  app — 207 distinct pids in five minutes on a busy host, each publishing a
  desktop-backend decision, and a CLI over ssh has no display. Filter
  `linux_desktop_backend_policy` by YOUR launched pid or it reads as a blind GUI.
- ⛔ **`input/unconsumed` cannot fire while the tty echoes** — the kernel line
  discipline answers for a cooked-mode shell. It sees raw-mode rows, which is
  every agent TUI, which is the case that matters.

All of these are also filed in `docs/agent-field-guide.md` and
`docs/observability.md`; this list is the index, not the owner.
