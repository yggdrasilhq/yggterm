## ⛔ LANDING: PUSH `HEAD:main` FIRST, THEN THE LANE — ordering, not a bypass

The push guard derives its range from the remote ref being pushed. A lane whose
remote tip is behind `main` therefore scans every commit `main` gained since —
other lanes' commits included — so **an already-remediated leak in someone
else's commit refuses your push**, and it is self-perpetuating because the push
that would advance the lane ref is the one being refused. `main`'s range is only
your own work. Same bytes either way; only the question the guard is asked
changes. This is filed in `docs/pending-bugs.md` under the guard entry.

⚠ **The remote lane ref is therefore stale at `071a7fce` and cannot advance.**
Nothing is stranded — every commit is on `main`. Do not "fix" it with
`YGG_PRIVACY_ALLOW=1`: this shape's whole danger is that it teaches the override
to people whose tree is clean.

⭐ **The order that matters: merge → test → push**, with the gates INSIDE the
retry loop (a gate run before a retry certifies a tree you did not push).

```sh
cargo test --workspace -- --test-threads=1          # serial
bash scripts/check-privacy.sh                       # its own call
bash scripts/check-docs-ssot.sh                     # its own call
bash scripts/check-queue-resurrection.sh --strict   # ⛔ --strict, or it exits 0 and gates NOTHING
git push origin HEAD:main && git push origin lane/dev/6.6-arsenal
git merge-base --is-ancestor HEAD origin/main       # the only check that cannot lie
```

⛔ **`git push … | tail && echo OK` tests the PIPE, not the push.** It announced
success on rejected pushes in three lanes today, mine included.

⛔ **Never rebase this lane** — it carries merge commits, and a rebase flattens
them. Merge `origin/main` in instead.

### 1. "A local launch into a cwd that exists only elsewhere leaves a HUSK row"
**Believed:** a keep-alive row that *never had a process*, plus a detector already present
and swallowed at the CC title poll's `local_cc_session_jsonl_path` lookup. **The owed work
was said to be: validate the cwd at launch, and un-swallow the detector.**

⛔ **Both halves were wrong, and reproducing it with a control is what showed it.**
- The launch **succeeds**. `best_effort_cwd_shell_prefix` walks up to the nearest existing
  ancestor and falls back to `$HOME`, deliberately; `claude --session-id <the row's own
  uuid>` was found running, in `$HOME`. No transcript existed only because CC writes one on
  its first turn. ⇒ **"validate the cwd at launch" would have refused a launch the product
  intentionally allows.** The real defect was that the row went on describing itself as
  *rooted at* a directory the process had never been in.
- The "swallowed detector" sits **behind a working-set gate**, so it was unreachable for a
  row that never ran. Two different faults shared one comment. The signal it names is real
  and now has its own home (`collect_stuck_launch_faults`), keyed on **mid-turn** rather
  than the working set — the looser key fires on every healthy launch before its first turn.
- ✅ **Shipped and live-verified against a control.** Entry removed from the queue.

## THE LANE'S LAWS — these cost real time to learn

- ⭐ **TABLE or FORK.** When a `match` arm or a per-CLI value looks per-binary, ask whether
  the TABLE forks or a single CELL does. `server app` was one table with one forked cell
  (launch) ⇒ full collapse. `server` mixes planes ⇒ per-verb, and a structural ban there
  would forbid a real fork.
- ⛔ **A fork can be replaced by a TABLE or by a GLOBAL, and only one is a fix.** The
  2026-08-13 intake did both in one function: slug-keyed settings (right) and one
  kind-blind env var for nine CLIs (wrong, and live in running daemons).
- ⭐ **Grep for the SETTER before believing an env read is a channel.** No setter anywhere
  ⇒ it is not a channel, it is inherited pollution.
- ⛔ **A source-scanning lock matches PROSE.** Three times in one session a lock matched its
  own comment or its own assertion string. Scan the product half
  (`source.split("mod tests {").next()`), strip `//` lines, and bound arms at their own
  close brace — indentation-sensitive bounds silently re-aim onto the next arm instead of
  failing.
- ⛔ **Two tests failing together are a claim about ONE cause. Read the second before
  editing the first.** The cheapest one to rationalise is the one that misleads you: one
  looked like a stale enum name and was, in fact, reporting a live regression that the
  second test made obvious.
- ⭐ **A number equal to a constant in the suspect path is the mechanism signing its own
  work** (`waited_ms: 180` == `PROBE_SETTLE`). Hunt for that before believing a story.
- ⛔ **Validate a source scanner against a case whose answer you already know.** My first
  verb extractor omitted `daemons` entirely because that verb uses a different dispatch
  spelling; only a live observation caught it.
- ⛔ **`~/gh` is PUBLIC.** Invent every example. The privacy guard refused a push of mine
  over an invented UUID ending in twelve digits — rewrite, never `YGG_PRIVACY_ALLOW=1`.
- ⛔ **Never end a turn on a question.** Owner-gated ⇒ `docs/owner-attention.md` with your
  recommendation and what you did meanwhile, then carry on.
