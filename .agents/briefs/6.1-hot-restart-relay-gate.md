## SECTION 2 — THE DEATH IS EXPLAINED. READ THIS BEFORE PROPOSING ANY MECHANISM.

Sessions were dying minutes after each deploy and the cause was open all night.
For the 464 s instance it is now closed, end to end, in the trace:

1. handover starts; the successor **accepts the fd and seats it**, and the **ack
   is lost**;
2. the predecessor books a failure and **resumes its own readers** ⇒ the key is
   genuinely owned by BOTH daemons;
3. seven sweeps, one a minute, all `NoneMoved` — the successor refusing with
   *"already runs a live PTY for it"*, **which is proof the first attempt
   worked**, read as the reason it failed;
4. something calls `terminal_ensure_new`; the **duplicate-prune** fires; a drop
   is `remove_session` → `shutdown` → **`kill`**;
5. the child dies. Same second as the transcript's last write.

⭐ **The killer is neither the handover nor the idle gate. It is the
DEDUPLICATION of a duplicate the handover's own failure manufactured.** Both
landed fixes attack it: `22f97c41` stops the duplicate existing, `d9966a7c`
stops the prune killing a shared child.

⛔ **SCOPE, and do not widen it:** `removed_terminal:true` appears exactly twice
in the whole corpus. **The 272 s and 402 s deaths have none of them and remain
UNEXPLAINED.** Do not retro-fit this onto them.

⛔ **Three mechanisms were proposed and refuted this session** — the 300 s idle
window (160 self-retire polls, **zero** idle-gate deferrals), the forced-past

**Do not re-adopt any of them.**

## SECTION 3 — THE DRAIN: UNBLOCKED, NOT YET EXERCISED

**Why the 14 legacy daemons never empty their hands:** one poisoned session pins
all of them. `classify_handoff_sweep` takes a `first_failure` and stops, so a
single stuck key held **eleven** healthy runtimes hostage (`readers_stood_down:
11, moved: 0`). That is fixed at the source; the sweep still aborts on first
failure, which is **worth doing next** — attempt every session, classify at the
end. ⚠ `Partial` must never exit the process; the code already knows that.

⚠ **A "release" in `progressive_migration` KILLS the pty and re-resumes** — read
`release_session_for_migration`'s docstring before calling it a move. And it is
gated on being re-resumable, so **a plain shell can never be released that way**;
those daemons say so themselves (*"a plain shell with no store to resume from; a
cold shutdown would destroy it"*).

⇒ The drain cannot be exercised until 3.0.155 deploys. **Do not evict anything.**

### ⛔ S1's CLOSING CLAUSE — "then it retires on its own" — AND WHERE IT CAN FAIL

The drain is *move sessions off, then let the emptied daemon retire.* The second
half is a real dependency, and a sibling lane has one counter-example: a sandbox
daemon with the gates apparently open **lived 48 minutes against a 90 s window**.

`daemon_should_idle_shutdown` has **three gates**, and reading it explains that:

1. `terminal_session_count > 0` ⇒ never retire. ⚠ **This counts OWNED +
   PRESERVED**, so a daemon holding only bequeathed records still refuses.
2. not yet idle for `idle_shutdown_ms` ⇒ no.
3. `active_client_instance_records` empty ⇒ retire. **Otherwise it retires only
   if `daemon_is_superseded(home_dir)`.**

⇒ **Gate 3 is the one the drain rests on.** On dev every legacy daemon IS
superseded, so once its hands are empty it should go. **A sandbox typically has
no superseding daemon**, so gate 3 fails and an emptied daemon lingers for ever —
which would explain the 48-minute observation without any defect in the drain.

⚠ **Unverified — I read the source, I did not reproduce the sandbox.** Check
whether that sandbox had a strictly-newer daemon alive before treating it as a
counter-example to S1.

⛔ **And note the fail-closed edge:** if `active_client_instance_records` returns
an **error**, the function returns `false`. A daemon whose client-record read
keeps failing never retires and nothing in the trace says why.

## SECTION 4 — THE BOOTER: STEP 2 IS DEAD, AND WHY

⛔ **The agent-row filter the settled design asked for does not exist and cannot
be written.** Measured across all 31 fields of a 378-row listing: the owner's
attended row and a delegate are identical — same `kind`, same `icon_kind`, same
tenancy, same presence. The separators are free text, identity, a folding flag,
transient `busy`, and a seat number an agent types about itself.

⇒ `never-arm.tsv` is not a backstop beneath a filter, **it IS the filter**, so
enumerate-and-arm is **fail-open**. `never_arm()`'s own docstring already rules
that such a path does not ship. **Do not build it.**

What exists instead: `ygg-booter.py coverage` sorts every live row into
`watched / never-arm / opted-out / retired / UNKNOWN` and **refuses to act on
UNKNOWN**. `retire` records a decided-dead row with evidence. ⚠ Auto-arm stays
unbuilt on purpose: it would resurrect rows that unsubscribed by finishing.

⚠ **~24 rows are still UNKNOWN.** Each needs a recorded decision, not a sweep.

## SECTION 5 — INSTRUMENTS THAT LIED THIS SESSION

- ⛔ **`terminal_session_keys` is OWNED + PRESERVED.** Use
  `owned_terminal_session_keys`. The old note attributed PTYs to whichever daemon
  merely held a bridge record.
- ⛔ **A process sweep must anchor on `argv[0]`** — read `/proc/<pid>/cmdline`,
  take the first NUL-separated field, require its basename to be the binary. The
  rule failed three times in one session in weaker forms: `pgrep -cf` counts your
  own shell; `grep -v grep` does not exclude the shell; matching `claude` against
  the whole cmdline matches every shell, because the snapshot path contains it.
- ⛔ **`~/.yggterm` trace files are shared with `cargo test`.** A corpus-wide
  count returned exactly the fixed behaviour — from a test binary. Filter by pid
  and confirm each pid is a daemon.
- ⛔ **`strings <binary> | grep <a json! KEY>` can read absent on a correct
  build.** Pick a literal that appears as a VALUE, cross-check with `nm`.
- ⛔ **`server daemons`: count VERSION rows, and allow for the `*`** on the
  serving daemon, which shifts every field by one. Indented `deferring:` lines
  interleave and vary with activity.
- ⛔ **"No rows died" cannot be established by watching a fixed interval.** I
  fitted a window to the previous maxima and missed a death at 464 s. Census by
  uuid, before and after, re-checked at the next relay boundary.
- ⛔ **A `docs-ssot` status line must be EXACTLY one of the three strings.**
