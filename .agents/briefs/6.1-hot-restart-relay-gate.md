## SECTION 1 — THE SETTLE WINDOW IS DONE AND PRODUCTION-PROVEN. DO NOT REOPEN IT.

A handover releases on the successor's **survival**, not its acceptance
(`40cbcaf0`, live from 3.0.149). ⭐ The idea: `crate::terminal::ReaderPark`
separates **holding a descriptor** from **serving a session** — a parked reader
blocks in `poll` over the pty AND a wake eventfd, so it stands down with **no
bytes in hand** and pending output waits in the kernel for whoever reads next. A
flag checked after a blocking read still swallows a chunk; that is why it is a
poll.

**Six real settle windows, three hosts, ~70 live runtimes**, every one
`settled:true` with `bytes_stolen_after_park: 0` and `successor_identified:true`:
dev held 24 then 23, *** 11, oc 4 + 4. A private-GUI capture across the window
showed the sidebar rendering the same four rows throughout — no duplicate, no
flicker. The persist-mute latch that would have left a recovered daemon serving
sessions it could never record is closed too (`8cb2068e`); ⛔ its three-poll run
length is the safety argument — **do not "simplify" it to one poll**, or a
merely-slow successor gets its state file overwritten.

Residual, filed and inherent: a successor that dies mid-window takes the ~1.5 s
it had already read (a bounded scrollback hole instead of the whole session).

### ⭐ I MEASURED THE INSTRUMENT FOR YOU, AND IT HAS A TRAP THAT WOULD HAVE FOOLED YOU

The falsifier needs *"which daemon owns this session"*. That question is
answerable — but **only one of the two obvious routes works**:

```sh
# ✅ WORKS — address a daemon by PID
yggterm-headless server status --endpoint <daemon-pid>   # → terminal_session_keys
# iterate the PIDs from `server daemons`; the one whose keys contain your
# session owns it. Verified: --endpoint 219756 → 2.12.14, owns 3.
```

⛔⛔ **NEVER ask this through a version-named SOCKET.** Every retired version's
socket is **aliased to the newest daemon** by the bequest, so
`--endpoint …/server-3-0-131.sock`, `…-150.sock` and `…-151.sock` all answered as
**the same pid 1099216 / 3.0.151 / 53 keys**. Three doors, one room, and the
answer looks unanimous while being meaningless. Measured 2026-08-14. ⇒ If it
holds, the fix is not "stop deploying" but **draining sessions off
pre-settle-window daemons**, or guaranteeing they never converge while owning
agent PTYs.

## SECTION 4 — TRAPS THAT COST REAL TIME

1. ⛔⛔ **`~/gh/yggterm` WILL DELETE YOUR UNCOMMITTED WORK.** A peer's
   `git reset --hard origin/main` took ~1200 lines: `git status` clean,
   `git stash list` empty, `git fsck` found no dangling blob, unrecoverable — it
   had to be retyped from context. **Work in your worktree and commit `wip(...)`
   checkpoints every few edits;** squash at the end.
2. ⛔ **`strings <binary> | grep <a name only your change adds>` before believing
   any test result.** A sandbox silently ran a stale binary for a whole cycle and
   `--version` said what I wanted to hear. `--version` cannot separate two builds
   inside one version number; `--build-commit` can.
3. ⛔ **`pipefail` + a glob that matches nothing = a detector that can never
   fire.** My sweep-watcher greped two paths, one absent; the left `grep` exited
   2, `pipefail` made the pipeline non-zero, and the `if` never fired while the
   line it wanted sat in the file.
4. ⛔ **Keep `YGGTERM_HOME` SHORT in sandboxes** (e.g. `/tmp/ygg-x`). A long path
   pushes the socket to `/run/user/<uid>/yggterm/h-<hash>/`, but
   `live_newer_daemon_socket` scans the HOME dir — so **supersession silently
   never fires** and no handover ever happens.
5. ⛔ **A test that spawns a pty READS the process-wide terminal-identity env**
   and must hold `codex_cli::env_test_guard`, or it makes the two identity tests
   in `lib.rs` flaky — not its own.
6. ⛔ **`server status` → `terminal_session_count` is PER-DAEMON.** It fires its
   loudest false alarm during a handover — mine cried `53 → 29` on a host that
   had gained sessions. Sum the `OWNED` column of `server daemons`. Field guide §1.
7. ⛔ **`server attach --help` CREATES a session named `--help`** and spawns a
   live `bash -i`. Interactive bash ignores SIGTERM; SIGHUP the exact pid.
