## SECTION 1 — THE SETTLE WINDOW IS DONE (`40cbcaf0`, on `origin/main`)

The two-second window that destroyed seven agent sessions is closed. The
predecessor holds its descriptors until the successor has SURVIVED a settle
interval (`YGGTERM_HANDOFF_SETTLE_MS`, default 10 s), and wakes its own readers
again if it has not.

⭐ **The idea worth keeping:** `crate::terminal::ReaderPark` separates HOLDING a
descriptor from SERVING a session. A parked reader blocks in `poll` over the pty
AND a wake eventfd, so it stands down with **no bytes in hand** — everything the
shell writes from that instant waits in the kernel for whoever reads next. That
is the only reason waiting is affordable: before it, a settle interval was a
double-read interval.

**Proven in a private sandbox, both controls**, 3.0.147 (the fix) handing over to
the shipped 3.0.148, so the *no-identity fallback* is the path that ran:

| control | result |
|---|---|
| successor SIGTERM'd 1.5 s in | `settled:false` · predecessor **ALIVE** · all 3 sessions still running |
| successor left alone | `settled:true` after 20 s · predecessor exits · successor serves all 3, **no gap** across the swap |

`bytes_stolen_after_park: 0` in both.

## SECTION 1b — AND THE HOLE THE RECOVERY PATH OPENED IS CLOSED TOO (`8cb2068e`)

`superseded_routine_persist_muted` was a **permanent latch**: once a newer daemon
was seen, this daemon never wrote `server-state.json` again. Correct while the
successor lives — and wrong the instant it does not, because the settle window
now hands the sessions BACK. A predecessor that took them back was the only
process serving them and the only process that would never record them, so a row
could be live and unrecorded, which is unrecoverable the moment anything signals
its holder.

⭐ **Cleared by the same loop, the same prober and the same question that SETS
it** — `live_newer_daemon_version` answering *nobody* — so the two answers cannot
drift apart. It needs **three consecutive clear polls (~60 s)**, and that run
length IS the safety argument: un-muting on one missed probe would overwrite a
HEALTHY successor's file whenever it was merely slow to answer its status probe.
⇒ **Do not "simplify" it to a single poll.**

## SECTION 4 — SANDBOX RECIPES THAT WORK

- ⛔⛔ **KEEP `YGGTERM_HOME` SHORT** (e.g. `/tmp/ygg-settle-home`). A long home
  pushes the socket out to `/run/user/<uid>/yggterm/h-<hash>/` — but
  `live_newer_daemon_socket` scans the HOME dir for `server-*.sock`, so
  **supersession silently never fires** and no handover ever happens. This cost
  a full run to find and looks exactly like "the daemon ignored me".
- **A daemon-only sandbox beats a GUI sandbox** for anything about handover:
  two `server daemon` processes in one private home, no sway, no GUI binary.
- **Make a session with `server attach <name> <cwd>`** — it CREATES a live shell
  on that daemon and the session outlives the client. ⚠ Pass a bare name:
  `server attach local://x` makes the key `local://local://x`.
  ⛔ And `server attach --help` **creates a session called `--help`** — the flag
  is read as a session name. That is a real verb defect, filed as a dream.
- **Two versions, one cold build:** build the fix at a version BELOW the shipped
  one (`3.0.147`) in a throwaway worktree and let the *installed* daemon be the
  successor. One build, and it exercises the backward-compatible path.
- ⛔⛔ **Match teardowns on your own `YGGTERM_HOME`**, never on a binary path.
- ⭐ **`strings <binary> | grep <your new trace name>`** before believing any
  sandbox result. Mine silently ran an OLD binary for a whole cycle, and the
  missing trace event was the only thing that gave it away.
